# CattleFeedAI — Supabase PostgreSQL Migration Guide

**Document Version:** 1.0.0  
**Target Engine:** PostgreSQL 14+ (Supabase Managed Cloud PostgreSQL)  
**ORM Framework:** Spring Boot 3.2.5 / Hibernate 6.4 (Spring Data JPA)

---

## 1. Overview of Database Migration

CattleFeedAI was previously configured to use MySQL 8. This migration upgrades the persistence architecture to **Supabase Managed PostgreSQL** using standard JDBC/JPA connectivity while:
1. Preserving all 16 business entities, relationships, primary keys, foreign keys, unique constraints, and indexes.
2. Maintaining `@Enumerated(EnumType.STRING)` mapping to `VARCHAR`, avoiding proprietary database enum types.
3. Converting `AUTO_INCREMENT` to standard `BIGINT GENERATED BY DEFAULT AS IDENTITY`, which is native to PostgreSQL and fully supported by Hibernate 6.
4. Preserving backwards compatibility for local development.
5. Retaining original MySQL scripts in `database/schema/schema.sql` for historical reference.

## 2. MySQL to PostgreSQL Datatype Conversion Matrix

| MySQL 8 Type | PostgreSQL 14+ / Supabase Type | Rationale |
| :--- | :--- | :--- |
| `BIGINT AUTO_INCREMENT PRIMARY KEY` | `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | SQL-standard identity column; allows sequence generation while supporting explicit ID inserts during data migrations. |
| `VARCHAR(n)` | `VARCHAR(n)` | Direct 1:1 match. String length bounds preserved. |
| `BOOLEAN` / `TINYINT(1)` | `BOOLEAN` | Native PostgreSQL boolean type (`TRUE` / `FALSE`). |
| `DATETIME` | `TIMESTAMP WITHOUT TIME ZONE` | Microsecond-accurate timestamp matching Java `LocalDateTime`. |
| `DATE` | `DATE` | Direct 1:1 match for Java `LocalDate`. |
| `DECIMAL(p, s)` | `NUMERIC(p, s)` | Exact precision and scale preserved for chemical parameters, weights, and GPS coordinates. |
| `TEXT` | `TEXT` | Variable-length text for notes, messages, and advisories. |
| `INT` | `INTEGER` | Direct 1:1 match for integers. |
| `ENGINE=InnoDB` | *(Omitted)* | MySQL-specific storage engine clause is discarded. |
| `utf8mb4_unicode_ci` | `UTF8` | Supabase instances default to UTF-8 encoding. |

## 3. Inventory of Tables (16 Entities)

| Table Name | Description | Key Relationships |
| :--- | :--- | :--- |
| `users` | Multi-tenant user accounts & roles (FARMER, VET, EXPERT, ADMIN) | Parent of farms, alerts, consultations, experts |
| `farms` | Farm profile, location, district, state, pin code | Many-to-One with `users` |
| `animals` | Livestock profiles, breeds, lactation stage, yields | Many-to-One with `farms` |
| `feed_samples` | Batches of dry/concentrate feed registered for testing | Many-to-One with `farms`, optional `animals` |
| `silage_samples` | Batches of fermented silage registered for testing | Many-to-One with `farms`, optional `animals` |
| `test_results` | Chemical analysis parameters (protein, moisture, aflatoxin, pH) | Foreign Key to `feed_samples` or `silage_samples` |
| `health_observations` | Routine clinical/appetite/digestive observations | Many-to-One with `animals` |
| `health_risks` | Non-diagnostic risk flags from rule-based screening engine | Many-to-One with `animals` |
| `advisories` | Tailored management recommendations and alerts | Many-to-One with `animals` |
| `experts` | Verified veterinarian and nutritionist professional profiles | One-to-One with `users` |
| `consultations` | Formal collaboration thread between farmer and expert | Foreign Keys to `users`, `experts`, `animals` |
| `feed_plans` | Scheduled daily ration workflows | Foreign Keys to `animals`, `experts` |
| `storage_units` | Godowns, bunkers, silos, and storage bays | Many-to-One with `farms` |
| `sensor_readings` | Telemetry logs (temperature, humidity, pH, gas, mould risk) | Many-to-One with `storage_units` |
| `alerts` | In-app notification queue with severity and read status | Many-to-One with `users` |
| `sample_images` | Physical image attachments for visual screening & audit | Foreign Keys to `feed_samples` or `silage_samples` |

## 4. How to Import the Schema into Supabase

### Option A: Using the Supabase Web Dashboard (Recommended)
1. Log into your [Supabase Dashboard](https://supabase.com/dashboard).
2. Select your project (or create a new project in the desired region, e.g., Singapore).
3. Navigate to the **SQL Editor** from the left navigation bar.
4. Click **New Query**.
5. Copy the entire contents of [`database/postgresql/schema.sql`](file:///d:/CattleFeedAI/database/postgresql/schema.sql) and paste it into the editor.
6. Click **Run** (Ctrl + Enter).
7. Inspect the output; all 16 tables, constraints, and indexes will be created.

### Option B: Using psql CLI
```bash
psql "postgresql://postgres.[PROJECT_REF]:[PASSWORD]@aws-0-[REGION].pooler.supabase.com:6543/postgres?sslmode=require" -f database/postgresql/schema.sql
```

## 5. Verification Commands

Run the following SQL queries in the Supabase SQL Editor to verify schema health:

### 1. Verify Table Count (Should return 16)
```sql
SELECT count(*) AS total_tables 
FROM information_schema.tables 
WHERE table_schema = 'public' 
  AND table_type = 'BASE TABLE';
```

### 2. Verify Primary Keys & Identity Sequences
```sql
SELECT table_name, column_name, is_identity
FROM information_schema.columns
WHERE table_schema = 'public' AND is_identity = 'YES'
ORDER BY table_name;
```

### 3. Verify Foreign Key Constraints
```sql
SELECT
    tc.table_name, 
    kcu.column_name, 
    ccu.table_name AS foreign_table_name,
    ccu.column_name AS foreign_column_name 
FROM information_schema.table_constraints AS tc 
JOIN information_schema.key_column_usage AS kcu
  ON tc.constraint_name = kcu.constraint_name
JOIN information_schema.constraint_column_usage AS ccu
  ON ccu.constraint_name = tc.constraint_name
WHERE tc.constraint_type = 'FOREIGN KEY'
ORDER BY tc.table_name;
```

## 6. Data Migration Procedure (From Existing MySQL to Supabase)

If you have existing data in a MySQL database that needs to be transferred to Supabase:

### Step 1: Export Data as CSV (Excluding Table DDL)
Run standard mysqldump or mysql export commands for each table:
```bash
# Example dumping tables with column headers as CSV
mysql -u [USER] -p[PASSWORD] -e "SELECT * FROM users" cattlefeedai > users.csv
```
Alternatively, use an automated migration tool such as `pgloader`:
```bash
# pgloader command for automated MySQL -> PostgreSQL schema and data sync
pgloader mysql://user:password@localhost/cattlefeedai postgresql://postgres.[PROJECT_REF]:[PASSWORD]@aws-0-[REGION].pooler.supabase.com:5432/postgres
```

### Step 2: Import into Supabase
Using `psql` or the Supabase dashboard table import:
```sql
\copy users (id, username, email, password_hash, role, phone, language, is_active, created_at, updated_at) FROM 'users.csv' WITH (FORMAT csv, HEADER true);
```

Because IDs are imported explicitly, ensure the PostgreSQL identity sequences start above the maximum imported ID:
