6. FRONTEND IMPLEMENTATION
--------------------------
- Expo-compatible Camera & Image Picker: Installed and configured `expo-camera` (~57.0.5) and `expo-image-picker` (~57.0.20).
- Reusable Camera Screen (`CameraCaptureScreen.tsx`):
  Supports both Feed and Silage samples via route parameters: `{ sampleType, sampleId, sampleCode }`.
  Provides multi-state flow:
  - 'CAMERA': Live camera preview (mobile CameraView or web HTML5 video stream), switch front/back camera, gallery select button, viewfinder framing guide.
  - 'PREVIEW': Displays captured or selected image, caption/note input field, "Retake" button, "Confirm & Upload" button.
  - 'UPLOADING': Non-blocking upload feedback with progress spinner.
  - 'PERMISSION_DENIED': Clear explanation with permission re-request button and fallback gallery button.
- Reusable Gallery Component (`SampleImageGallery.tsx`):
  Integrated into both FeedDetailsScreen and SilageDetailsScreen. Displays photo count, thumbnail cards with filename, date, caption, file size, full-screen image viewer modal, and delete button with confirmation dialog.


7. BACKEND IMPLEMENTATION
-------------------------
- SampleImage JPA Entity (`sample_images` table):
  Attributes: id, feedSample (ManyToOne), silageSample (ManyToOne), originalFilename, storedFilename (unique UUID), filePath, fileReference, contentType, fileSize, caption, createdAt.
- SampleImageService:
  Handles secure disk storage in configured application directory (`uploads/sample-images/`), enforces maximum file size (10MB), checks allowed content types (image/jpeg, image/png, image/webp), sanitizes original filenames, generates collision-resistant UUID storage names, prevents directory traversal, and enforces farm ownership.
- SampleImageController:
  Exposes REST endpoints for multipart upload, image listing, single image metadata, binary file streaming, and deletion.


8. API ENDPOINTS
----------------
Feed Sample Image Endpoints:
- POST   /api/feed-samples/{feedSampleId}/images
  Uploads photo attachment (multipart/form-data: file, optional caption). Returns 201 Created with SampleImageResponse.
- GET    /api/feed-samples/{feedSampleId}/images
  Lists all images attached to the feed sample. Returns 200 OK.
- GET    /api/feed-samples/{feedSampleId}/images/{imageId}
  Retrieves metadata for a specific feed sample image. Returns 200 OK.
- GET    /api/feed-samples/{feedSampleId}/images/{imageId}/file
  Streams binary image file with Content-Type header. Returns 200 OK.
- DELETE /api/feed-samples/{feedSampleId}/images/{imageId}
  Deletes image record and removes stored file from disk. Returns 204 No Content.

Silage Sample Image Endpoints:
- POST   /api/silage-samples/{silageSampleId}/images
  Uploads photo attachment for silage sample. Returns 201 Created with SampleImageResponse.
- GET    /api/silage-samples/{silageSampleId}/images
  Lists all images attached to the silage sample. Returns 200 OK.
- GET    /api/silage-samples/{silageSampleId}/images/{imageId}
  Retrieves metadata for a specific silage sample image. Returns 200 OK.
- GET    /api/silage-samples/{silageSampleId}/images/{imageId}/file
  Streams binary image file with Content-Type header. Returns 200 OK.
- DELETE /api/silage-samples/{silageSampleId}/images/{imageId}
  Deletes image record and removes stored file from disk. Returns 204 No Content.


9. IMAGE STORAGE APPROACH
-------------------------
- Architecture: Controlled application directory (`uploads/sample-images/`) on local filesystem.
- Filename generation: `UUID.randomUUID().toString() + extension`. Original filenames are sanitized and stored separately in metadata for display.
- Database: Stores file metadata and references; binary blob data is NOT stored directly in MySQL tables to prevent database bloat.
- Reference URL: `/api/feed-samples/{id}/images/{imageId}/file` and `/api/silage-samples/{id}/images/{imageId}/file`.


10. SECURITY
------------
- Authentication: All upload, list, download, and delete endpoints require a valid JWT token (Authorization: Bearer <token>). Unauthenticated requests return 401 Unauthorized.
- Farm Ownership: Strict verification ensures the authenticated user owns the farm that owns the feed or silage sample. Farmer B cannot upload, view, or delete Farmer A's sample images (returns 403 Forbidden).
- Path Traversal Protection: Normalized absolute paths are checked to ensure they reside strictly within the configured storage directory.
- Denial-of-Service Protection: File size capped at 10MB; invalid content types rejected before processing.


11. CAMERA BEHAVIOR (MOBILE)
----------------------------
- Uses `CameraView` from `expo-camera`.
- Requests camera permission via `useCameraPermissions()`.
- Supports front and back camera switching (`facing`).
- Captures frame with `takePictureAsync({ quality: 0.85 })`.
- Provides immediate full-screen review before upload.


12. WEBCAM BEHAVIOR (PC / WEB)
------------------------------
- On Web platforms (`Platform.OS === 'web'`), accesses the browser webcam feed via standard HTML5 `navigator.mediaDevices.getUserMedia({ video: ... })`.
- Displays real-time `<video>` preview.
- Captures high-resolution frame via `<canvas>` element and converts to JPEG Data URL.
- Cleans up media stream tracks immediately upon capture or unmount.


13. GALLERY / FILE PICKER
-------------------------
- Provided as a seamless alternative on all platforms using `expo-image-picker` (`launchImageLibraryAsync`).
- Accessible directly from CameraCaptureScreen ("Gallery" button) and from SampleImageGallery ("Gallery" button).
- Enables image selection when camera permission is declined or on emulators.


14. VALIDATION
--------------
- Frontend validation (`sampleImageService.validateImage`): Checks URI presence, file size <= 10MB, allowed MIME types (JPEG, PNG, WebP).
- Backend validation (`SampleImageService.validateImageFile`): Verifies file non-empty, file size <= 10MB, allowed Content-Type headers.

21. SCIENTIFIC BOUNDARIES
-------------------------
- M6.6 strictly performs image capture, storage, and reference handling.
- ZERO computer vision or AI inference is executed in M6.6.
- ZERO chemical parameters (protein, moisture, aflatoxin, fiber, pH) are predicted from images.
- ZERO disease diagnoses are performed.
