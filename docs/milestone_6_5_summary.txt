2. ACTUAL HEALTH-RELATED BACKEND ARCHITECTURE
---------------------------------------------
The Spring Boot backend architecture decouples diagnostic veterinary practice from feed/nutritional risk screening:
1. AnimalHealthScreeningService.screenAnimalHealth(Long animalId) serves as the centralized screening engine.
2. Ownership is strictly verified: The animal must belong to a farm owned by the authenticated JWT user.
3. Multi-source data synthesis:
   - Animal profile: Lactation stage (EARLY, MID, LATE, DRY), days in milk, milk production per day, feed intake status.
   - Feed & Silage history: Queries all feed and silage samples tied to the animal via FeedSampleRepository and SilageSampleRepository.
   - Lab/Sensor Test Results: Retrieves test results for each sample (moisture, crude protein, aflatoxin, mould, spoilage, etc.).
   - Health Observations: Queries HealthObservationRepository for recent observations recorded for the animal.
4. Non-Diagnostic Screening Rules:
   - Nutritional demand check: If an animal is in EARLY or MID lactation yielding >= 12.0 L/day, feed with crude protein < 16.0% triggers a Nutritional Risk indicator (Severity: WARNING).
   - Contamination & Feed Intake check: If feed moisture > 14.0% or mould/spoilage is detected, and animal feed intake is REDUCED, a Contamination Exposure Risk indicator is triggered (Severity: HIGH).
5. Output Classification:
   - INSUFFICIENT_DATA: Missing feed samples, test results, or animal parameters. Returns a detailed missingInformation list.
   - POTENTIAL_CONCERN: Feed/nutritional/storage risks identified. Persists HealthRisk records and returns detectedRisks.
   - HEALTHY_NO_RISK_DETECTED: Feed testing data present and within acceptable thresholds for the animal's profile.
6. Non-Diagnostic Terminology & Legal Disclaimer:
   - Every response includes an official disclaimer: "This is a screening tool and does not provide a veterinary diagnosis. Consult a qualified veterinarian or veterinary nutritionist for clinical assessment."


3. ACTUAL ENDPOINTS DISCOVERED
------------------------------
Animal Health Screening (AssessmentController):
- GET  /api/assessments/animals/{animalId}/health-screening
  Executes animal health screening, synthesizes animal profile with feed/silage history and test results, generates/persists health risks, and returns AnimalHealthScreeningResponse.

Supporting Animal-Linked Endpoints:
- GET  /api/animals/{id}
  Retrieves animal profile details.
- GET  /api/feed-samples?animalId={id}
  Retrieves feed samples associated with the animal.
- GET  /api/silage-samples?animalId={id}
  Retrieves silage samples associated with the animal.
- GET  /api/test-results/feed-sample/{feedSampleId}
  Retrieves lab and sensor test results for a feed sample.
- GET  /api/test-results/silage-sample/{silageSampleId}
  Retrieves test results for a silage sample.
- GET  /api/advisories?animalId={id}
  Retrieves persisted herd advisories generated for the animal.
- GET  /api/assessments/feed-samples/{feedSampleId}
  Retrieves quality assessment for a feed sample.
- GET  /api/assessments/silage-samples/{silageSampleId}
  Retrieves quality assessment for a silage sample.

5. WHETHER DEDICATED HEALTH SCREENING API EXISTS
------------------------------------------------
YES. The backend provides a dedicated endpoint:
GET /api/assessments/animals/{animalId}/health-screening
This endpoint is live in AssessmentController.java and powered by AnimalHealthScreeningService.java.

Architecture Note on Health Observations & Health Risks:
HealthObservation and HealthRisk exist as JPA entities in the database with repositories (HealthObservationRepository, HealthRiskRepository), but the backend does not expose separate CRUD REST controllers for them. Instead, screening evaluation, observation counts, and health risk persistence are encapsulated inside the GET /api/assessments/animals/{animalId}/health-screening workflow. The frontend respects this architecture and does not create mock or non-existent endpoints.
