================================================================================
CattleFeedAI — Milestone 12 (M12): Integrated Decision Support Summary
AI + Expert Consultation + Analytics Enhancement
================================================================================

1. OBJECTIVE
--------------------------------------------------------------------------------
Milestone 12 (M12) is a software-only integration and enhancement milestone connecting
the existing CattleFeedAI functional domains from Milestones M1–M11:
- AI Visual Screening (M7)
- Feed / Silage Sample Inventory (M2, M3)
- Laboratory Test Results (M4)
- Rule-based Quality Assessment (M5)
- Risk Assessment (M5)
- Animal Health Risk Screening (M6)
- Feed Plans & Ration Records (M11)
- Advisories & Notifications (M5, M10)
- Expert Consultations (M8)
- Historical Analytics (M9)

This provides an authoritative, evidence-based decision-support workflow for farmers,
veterinarians, and animal nutrition experts without redesigning working architecture,
creating duplicate services, or fabricating scientific calculations.


2. INTEGRATED ARCHITECTURE
--------------------------------------------------------------------------------
The M12 core workflow forms a closed-loop decision support cycle:

Animal Profile (Tag, Lactation, Yield)
   +
Feed / Silage Sample Information (Origin, Photos)
   +
Laboratory Test Results (Moisture, CP, Fiber, pH)
   +
Rule-Based Quality Assessment (GOOD, ACCEPTABLE, etc.)
   +
Risk Assessment (Contamination, Spoilage, Nutritional)
   +
AI Visual Screening (Surface Characteristics / Discoloration)
   +
Animal Health Screening (Observations & Dietary correlation)
   +
Active Feed Plans (Ration Schedules)
   +
Historical Records & Analytics
        ↓
Unified Evidence Summary Aggregation Layer (EvidenceSummaryService)
        ↓
Expert Consultation (Farmer Submits Case)
        ↓
Expert Review (Comprehensive Unified Evidence View)
        ↓
Professional Response (Veterinarian / Veterinary Nutritionist Advisory)
        ↓
Farmer (Inspects Unified Findings & Action Plan)
        ↓
Historical Analytics & Monitoring (Track Long-Term Progression)


3. EVIDENCE AGGREGATION ARCHITECTURE
--------------------------------------------------------------------------------
The backend introduces a dedicated orchestration and aggregation layer:
- Service: `com.cattlefeedai.api.service.evidence.EvidenceSummaryService`
  * Pure orchestration: delegates to existing authoritative services:
    - `AnimalRepository`, `FeedSampleRepository`, `SilageSampleRepository`, `TestResultRepository`
    - `QualityAssessmentService` (reused as-is)
    - `RiskAssessmentService` (reused as-is)
    - `AnimalHealthScreeningService` (reused as-is)
    - `AiServiceClient` (reused as-is)
    - `AdvisoryService` (reused as-is)
    - `FeedPlanService` (reused as-is)
    - `AnalyticsService` (reused as-is)
  * NO scientific recalculations or formula reimplementation.
  * Absence of data strictly yields null, empty collections, or "Not Available".
  * Data fabrication is strictly prevented.


4. EVIDENCE APIS
--------------------------------------------------------------------------------
Minimal, highly-cohesive REST endpoints exposed via `EvidenceController`:

1. GET /api/evidence/animals/{animalId}
   - Aggregates animal profile, feed/silage samples, latest lab test results,
     rule-based quality evaluation, risk assessment, visual screening, health
     screening, active feed plans, recent advisories, and historical summary.
   - Authorized for: Animal owner (Farmer), consultation-assigned Expert, or Admin.

2. GET /api/evidence/consultations/{consultationId}
   - Aggregates the consultation context, patient animal, associated feed/silage,
     test results, assessments, feed plans, and historical baseline.
   - Authorized for: Consultation requester (Farmer), assigned Expert, or Admin.

Response Structure (EvidenceSummaryResponse):
{
  "animal": { ... },
  "consultation": { ... },
  "feedEvidence": [ ... ],
  "silageEvidence": [ ... ],
  "testEvidence": [ ... ],
  "qualityEvidence": { ... },
  "riskEvidence": { ... },
  "visualScreeningEvidence": { ... },
  "healthScreeningEvidence": { ... },
  "feedPlans": [ ... ],
  "advisories": [ ... ],
  "historicalSummary": { ... },
  "disclaimer": "This evidence summary combines available recorded, laboratory, screening, and historical information for decision support. AI visual screening evaluates image characteristics only and does not measure chemical composition or provide veterinary diagnosis. Professional interpretation should be obtained from a qualified Veterinarian or Veterinary Nutritionist."
}

6. AI INTEGRATION & SOURCE TRANSPARENCY
--------------------------------------------------------------------------------
- Full reuse of existing M7 FastAPI AI microservice pipeline.
- Analysis Source Transparency:
  * `ML_VISUAL_SCREENING` is displayed with model version (e.g. v0.3.0) when ML is available.
  * `DETERMINISTIC_VISUAL_SCREENING` is explicitly shown when fallback heuristics are used.
  * The UI never labels deterministic results as ML.
- Visual Screening Scope:
  * Limited strictly to physical surface characteristics: mould, spoilage, discoloration, foreign materials.
  * Disclaimers explicitly reinforce that visual screening DOES NOT predict crude protein,
    moisture, fiber, energy, minerals, urea, pH, or veterinary disease.

9. SECURITY & DATA ISOLATION
--------------------------------------------------------------------------------
Multi-tenant security enforced at Spring Security and service layers:
- FARMER: Restricted strictly to own User -> Farm -> Animal -> Samples hierarchy.
  * Cross-farmer animal evidence request -> 403 Forbidden.
  * Cross-farmer consultation evidence request -> 403 Forbidden.
- EXPERT: Evidence access granted ONLY when consultation is assigned to that expert.
  * Unassigned expert accessing consultation evidence -> 403 Forbidden.
  * Assigned expert accessing consultation evidence -> 200 OK.
- ADMIN: System-wide decision-support access.
- Unauthenticated requests -> 401 Unauthorized.
- Non-existent animal or consultation -> 404 Not Found.
- Cross-farmer evidence leakage: 0 instances.


10. SCIENTIFIC BOUNDARIES & SAFETY
--------------------------------------------------------------------------------
- Platform classification: Non-diagnostic decision-support and screening platform.
- Strictly prohibited terminology maintained: "dietician" is rejected in favor of
  "Veterinarian", "Veterinary Nutritionist", and "Animal Nutrition Expert".
- Diagnostic boundaries: Does not provide veterinary disease diagnosis, treatment
  prescriptions, or automated diet formulation.
- Preserved terminology: "Potential Risk", "Risk Indicator", "Possible Feed-Related Concern",
  "Visual Screening", "Evidence Summary", "Professional Advisory".
- Mandatory evidence disclaimer displayed prominently on the summary screen.

14. KNOWN LIMITATIONS
--------------------------------------------------------------------------------
- Evidence aggregation requires network connectivity to backend; offline evidence caching is out of scope.
- In-depth chemical analysis remains reliant on physical laboratory testing; AI visual screening is strictly confined to surface characteristics.
- Push notifications, SMS, WhatsApp, and background schedulers are excluded by specification.
