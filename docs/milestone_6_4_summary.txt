2. ACTUAL M5 BACKEND ARCHITECTURE DISCOVERED
-------------------------------------------
The Spring Boot M5 architecture decouples parameter storage from scientific evaluation:
1. TestResult stores 11 physical/chemical measurements (Moisture, Crude Protein, Fiber, Energy Value, Aflatoxin, Mycotoxin, pH, Mineral Status, Adulteration, Mould Detected, Spoilage Detected).
2. QualityAssessmentService runs a configurable RuleEngineService over the TestResult parameters. Null measurements are strictly treated as "not available" (never converted to 0 or normal).
3. QualityStatus is evaluated as GOOD, ACCEPTABLE, NEEDS_ATTENTION, UNSAFE, or INSUFFICIENT_DATA.
4. RiskAssessmentService groups triggered rules into Contamination, Nutritional, and Storage/Spoilage risk categories and computes overall RiskLevel (LOW, MEDIUM, HIGH). Non-diagnostic terminology is enforced via official screening disclaimers.
5. AdvisoryService converts identified risk indicators into prioritized herd advisories (HIGH, MEDIUM, LOW) and automatically persists them to the database when the test sample is associated with an animal.
6. AdvisoryController manages listing, single-item retrieval, and marking advisories as read (PUT /api/advisories/{id}/read).


3. ACTUAL ENDPOINTS DISCOVERED
------------------------------
Quality & Risk Assessment (AssessmentController):
- GET  /api/assessments/test-results/{testResultId}
  Evaluates 11 parameters from a test result against baseline rules and returns QualityAssessmentResponse.
- GET  /api/assessments/test-results/{testResultId}/risk
  Identifies contamination risks, nutritional imbalances, and storage/spoilage risks and returns RiskAssessmentResponse.
- POST /api/assessments/test-results/{testResultId}
  Evaluates quality and risk layers and generates/persists advisories for the animal associated with the sample, returning AssessmentSummaryResponse.
- GET  /api/assessments/feed-samples/{feedSampleId}
  Evaluates the most recent test result recorded for a feed sample.
- GET  /api/assessments/silage-samples/{silageSampleId}
  Evaluates the most recent test result recorded for a silage sample.

Advisories (AdvisoryController):
- GET  /api/advisories
  Retrieves generated advisories for the authenticated farmer's herd, optionally filtered by ?animalId={id}&isRead={boolean}.
- GET  /api/advisories/{id}
  Retrieves a specific advisory message and recommended action by ID.
- PUT  /api/advisories/{id}/read
  Updates an advisory status to read (isRead = true).

11. RISK UI
-----------
Risks are grouped into backend categories:
- Contamination Risks (e.g. Aflatoxin, Mycotoxin, Adulteration)
- Nutritional Imbalances (e.g. Low Crude Protein, Fiber imbalance)
- Storage & Spoilage Risks (e.g. Mould, Spoilage, Silage pH deviation)
When no risks are detected, displays clean positive status ("No Elevated Risk Indicators").
Screening disclaimer from backend is clearly displayed.


12. ADVISORY UI
---------------
- Shows prioritized herd advisories from backend.
- Displays priority badge (HIGH in red, MEDIUM in amber, LOW in green).
- Displays linked animal tag if the sample was tied to a cattle record.
- Allows marking an advisory as read with instant optimistic UI update.
- Empty states for zero advisories or all read.


13. INSUFFICIENT DATA HANDLING
------------------------------
- Null or missing measurements in test results are rendered as "Not Available".
- Missing values are NEVER coerced to 0, false, "Good", or "Normal".
- When a test result lacks required parameters, backend returns QualityStatus.INSUFFICIENT_DATA and frontend displays the "Insufficient Data" badge with clear explanation that additional lab metrics are needed.


14. ERROR HANDLING
------------------
- Handled HTTP 400, 401, 403, 404, 409, 500, network timeouts, and offline states.
- Reuses existing `ErrorMessage.tsx`, `LoadingView.tsx`, and `getFarmerFriendlyErrorMessage()`.
- Unauthorized requests prompt authentication flow; forbidden requests show ownership access denial; not found shows resource missing; server errors show friendly retry state.
