5. NAVIGATION ARCHITECTURE
--------------------------------------------------------------------------------
The navigation architecture uses a conditional rendering pattern:
- RootNavigator observes `isAuthenticated` and `isLoading` from `useAuth()`.
  1. Startup / Loading: Renders `<LoadingView message="Restoring farm session..." />`
  2. Unauthenticated: Renders `<AuthNavigator />` (Stack: Login <-> Register)
  3. Authenticated: Renders `<AppNavigator />` (Stack: Dashboard, and ready for Farms, Animals, Feed, Silage, Assessments, Advisories, Profile)
- This ensures authenticated state transitions happen instantaneously without manual reset calls or state desynchronization.

--------------------------------------------------------------------------------
6. API CLIENT ARCHITECTURE
--------------------------------------------------------------------------------
- Built on modern native `fetch` with zero unnecessary third-party overhead.
- Centralized `API_BASE_URL` resolved dynamically via `src/constants/config.ts`:
  * Android Emulator: `http://10.0.2.2:8080`
  * iOS Simulator / Web: `http://localhost:8080`
  * Physical Device / LAN: Overridable via `process.env.EXPO_PUBLIC_API_BASE_URL`
- Automatic injection of `Authorization: Bearer <JWT>` header via `getToken()`.
- Timeout handling: 15,000ms timeout managed via native `AbortController`.
- Centralized 401 Unauthorized listener: Automatically clears invalid tokens and invokes logout, transitioning the UI back to Login cleanly.
- Unified response parser: Converts Spring Boot `ErrorResponse` into structured `AppApiError`.

--------------------------------------------------------------------------------
7. JWT STORAGE APPROACH
--------------------------------------------------------------------------------
- Implemented in `src/storage/tokenStorage.ts`.
- Uses `expo-secure-store` on iOS (Keychain) and Android (Keystore) with `WHEN_UNLOCKED_THIS_DEVICE_ONLY` policy.
- Contains automatic in-memory fallback for headless environments, unit tests, and SSR.
- Passwords are NEVER persisted.
- JWT tokens are NEVER logged to console or exposed in UI logs.
- Methods provided: `saveToken`, `getToken`, `removeToken`, `saveUser`, `getUser`, `clearAuthentication`.

--------------------------------------------------------------------------------
8. AUTHENTICATION STATE FLOW
--------------------------------------------------------------------------------
1. App Mounts: `AuthProvider` initializes with `isLoading = true`.
2. Token Check: Asynchronously checks `tokenStorage.getToken()`.
3. Token Found: Restores `user` and `token` state; sets `isAuthenticated = true`, `isLoading = false`.
4. Token Not Found: Sets `isAuthenticated = false`, `isLoading = false`.
5. Login Action:
   - Farmer enters credentials and presses "Sign In to Farm".
   - `authService.login()` issues `POST /api/auth/login`.
   - Token & user profile stored securely; state updated; router transitions to Dashboard.
6. Register Action:
   - Farmer enters username, email, password, phone, language.
   - `authService.register()` issues `POST /api/auth/register`.
   - Backend automatically sets role to FARMER and returns 201 Created with JWT.
   - Token & user profile stored; router transitions to Dashboard.
7. Logout Action:
   - Clears token and user metadata from secure storage.
   - Sets state to unauthenticated; router transitions to LoginScreen.
