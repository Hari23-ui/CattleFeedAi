1. PROJECT OVERVIEW & OBJECTIVE
--------------------------------------------------------------------------------
CattleFeedAI is an accessible, digital-first platform designed to address the 
lack of affordable quality assessment tools for cattle feed and silage among 
Indian dairy farmers. Poor quality feed directly reduces milk yield and quality,
causes nutritional deficiencies, and exposes livestock to health risks.

Key Value Propositions:
- Manual & Sensor-based Quality Assessment: Structured input of sensory, physical,
  and chemical parameters for cattle feed and silage.
- Animal Health & Profile Management: Complete history tracking per livestock 
  (milking status, lactation stage, weight, pregnancy status).
- Trend Analysis & Visual History: Historical tracking of test results over time.
- Rule-based Advisory Engine: Actionable recommendations for feed formulation, 
  storage, preservation, and feeding adjustments.
- Health Risk Screening: Early warning flags for potential nutritional and 
  toxicological issues (e.g., acidosis, ketosis, mycotoxin/aflatoxin exposure).
  *Note: Screening only; non-diagnostic.
- Hardware-Independent Architecture: Starts purely software/manual-entry driven, 
  with seamless plug-and-play support for future IoT (ESP32), NIR spectroscopy, 
  and AI/ML computer vision.

4. DATABASE SCHEMA (15 Core Entities Implemented)
--------------------------------------------------------------------------------
1.  users               - Authentication, credentials, role (FARMER, EXPERT, ADMIN)
2.  farms               - Farm profile, owner relation, location, district, state
3.  animals             - Livestock profiles (tag, breed, lactation, yield, weight)
4.  feed_samples        - Recorded feed batches/samples submitted for quality testing
5.  silage_samples      - Dedicated silage batches with fermentation indicators
6.  test_results        - Physical, sensory, and chemical test measurements
7.  health_observations - Farmer-logged observations (appetite, milk, behavior)
8.  health_risks        - Rule-derived risk assessments linked to samples & observations
9.  advisories          - Actionable feeding, storage, and health guidance
10. experts             - Veterinary/dairy nutritionist profiles
11. consultations       - Farmer-to-expert consultation threads and recommendations
12. feed_plans          - Prescribed feeding schedules and nutritional targets
13. storage_units       - Silos, bunker silos, pits, and warehouses on the farm
14. sensor_readings     - Environmental readings (temperature, humidity, moisture)
15. alerts              - Push/system alerts for risks, tasks, and advisories


5. CURRENT IMPLEMENTATION STATUS
--------------------------------------------------------------------------------
[COMPLETED]
1. Database Schema & Entities:
   - Full MySQL relational schema with FK constraints and indexes (schema.sql).
   - 15 JPA entities and 20+ domain enumerations.
   - 15 Spring Data JPA repositories with custom query methods.
2. Authentication Foundation (JWT + BCrypt):
   - User registration (`POST /api/auth/register`) with immediate JWT issuance.
   - User login (`POST /api/auth/login`) with credential validation.
   - Stateless JWT filter pipeline, UserDetailsService, and password encoder.
   - Role-based authorities (`ROLE_FARMER`, `ROLE_EXPERT`, `ROLE_ADMIN`).
3. Farm & Animal Management REST APIs:
   - Farm CRUD: `/api/farms` (`POST`, `GET`, `GET /{id}`, `PUT`, `DELETE`).
   - Animal CRUD: `/api/animals` (`POST`, `GET`, `GET /{id}`, `PUT`, `DELETE`).
   - Strict hierarchical ownership enforcement (`User -> Farm -> Animal`).
   - Intra-farm unique animalTag validation.
   - 46 integration tests verified passing via `test_farm_animal.ps1`.
4. Feed & Silage Sample Management + Test Result Recording:
   - FeedSample CRUD: `/api/feed-samples` (`POST`, `GET`, `GET /{id}`, `PUT`, `DELETE`).
   - SilageSample CRUD: `/api/silage-samples` (`POST`, `GET`, `GET /{id}`, `PUT`, `DELETE`).
   - TestResult Recording: `POST /api/test-results`, `GET /api/test-results/{id}`.
   - Chronological Test History: `GET /api/feed-samples/{sampleId}/test-results`
     and `GET /api/silage-samples/{sampleId}/test-results`.
   - Immutable historical data preservation (new records per test, never overwritten).
   - Strict ownership chain (`User -> Farm -> Animal -> Sample`).
   - Global sampleCode uniqueness enforcement.
   - 76 integration tests verified passing via `test_feed_silage.ps1`.
5. Quality Assessment & Advisory Engine (Milestone 5):
   - Configurable Rule Engine architecture (RuleRegistry, 9 rules, non-hardcoded placeholder thresholds).
   - Quality Assessment Service evaluating 11 parameters (Moisture, Crude Protein, Fiber, Energy,
     Aflatoxin, Mycotoxin, pH, Minerals, Adulteration, Mould, Spoilage).
   - Null-handling: NULL strictly means "not available", never 0 or auto-fail.
   - QualityStatus: GOOD, ACCEPTABLE, NEEDS_ATTENTION, UNSAFE, INSUFFICIENT_DATA with detailed explanations.
   - Risk Assessment Layer: Categorizes Contamination, Nutritional, and Storage/Spoilage risks using
     non-diagnostic terminology ("Potential Risk", "Risk Indicator", "Possible Feed-Related Concern").
   - Advisory Engine: Generates prioritized advisories, persists to database when animal linked,
     and tracks read/unread status (`/api/advisories`).
   - Animal Health Risk Screening: Correlates animal profile, feed test history, and health observations.
     Returns INSUFFICIENT_DATA when records are missing.
   - Webcam / Computer Vision Ingestion: Receives external CV visual screening payloads marked
     explicitly as VISUAL SCREENING ONLY (cannot chemically measure protein, moisture, etc.).
   - Security & Multi-tenancy: Cross-farmer access rejected with 403 Forbidden; system-wide ADMIN access.
   - 11/11 Maven unit tests (`AssessmentEngineUnitTest.java`) & 62/62 integration tests (`test_assessment_engine.ps1`).

6. EXECUTION QUICK REFERENCE
--------------------------------------------------------------------------------
Backend:
  cd backend/cattle-feed-api
  mvn spring-boot:run
  (Default URL: http://localhost:8080)

  Integration Tests:
  powershell -ExecutionPolicy Bypass -File test_farm_animal.ps1       # 46 tests
  powershell -ExecutionPolicy Bypass -File test_feed_silage.ps1       # 76 tests
  powershell -ExecutionPolicy Bypass -File test_assessment_engine.ps1  # 62 tests
  mvn test                                                           # 11 unit tests
  (Total Automated Tests: 195/195 Passing)

Frontend:
  cd frontend/cattle-feed-app
  npx expo start
  (Scan QR code with Expo Go, or run 'a' / 'w')

AI Microservice:
  cd ai-service
  uvicorn app.main:app --reload --port 8000
  (Default URL: http://localhost:8000, Swagger: http://localhost:8000/docs)
